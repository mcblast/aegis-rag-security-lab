# AI Incident Response Guide

AI security incidents should be triaged using clear evidence, affected system boundaries, and user impact. Teams should preserve prompts, retrieved context, model responses, source documents, timestamps, and application logs.

A RAG incident may involve prompt injection, poisoned documents, sensitive data leakage, broken access control, or unsafe model output. Response teams should identify whether the failure occurred in the user input layer, retrieval layer, context builder, model layer, output validation layer, or monitoring layer.

Baseline Phase 01 only provides source-aware output. Later phases will add audit logging, risk scoring, attack simulation, and incident evidence capture.
